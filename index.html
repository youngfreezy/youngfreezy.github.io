Signet Jewelers / AI Foundry

A shared platform for useful agents.

An internal agent studio backed by a governed Bedrock gateway and streaming chat.

Engineering / Architecture & tradeoffs

A governed model gateway with a resilient chat interface.

01Request path
Internal agents send model traffic through a shared Amazon Bedrock gateway. Budgets and rate limits apply per team; response caching reduces repeated work.
02Streaming transport
Chat streams incremental text. Keep-alive heartbeats protect long responses from CDN idle timeouts without treating those heartbeats as answer content.
03Operations
Token metrics are attributed by team, model, and project. Model rerouting and shutoff are configuration changes, so operators can respond without a code deployment.
ELI8 / How it works

One front door for many agents.

The studio gives people a place to build document-search agents. A shared gateway manages model traffic, and the chat interface shows long answers as a stream.

01Configure
Teams build agents around their own documents.
02Govern
The gateway applies team budgets, rate limits, and response caching.
03Keep connected
A small keep-alive signal tells the connection to stay open while the answer is being prepared.

Polaris IO / PioWorkflow

A workflow around the coding agent.

Planning, implementation, review, and QA with durable state and two human comprehension gates.

Engineering / Architecture & tradeoffs

A file-backed workflow across multiple coding tools.

01Context + state
Each command runs in a clean context and loads task-relevant material. Repository files and Git retain plans, progress, decisions, and evidence between commands.
02Gates + review
Plan and diff comprehension gates are advisory by default and can be enforced by configuration. Cross-model reviews examine the plan and implementation before the PR workflow proceeds.
03Verification + recovery
Small commits and saved progress let work resume without relying on chat memory. Post-merge QA records PASS, FAIL, BLOCKED, or SKIPPED with evidence; qualified passing cases feed automation planning.
ELI8 / How it works

The memory lives outside the conversation.

A ticket moves through a series of focused commands. Each command starts fresh and reads the plans, code, and progress saved by the previous step.

01Two teaching gates
A person explains the plan before work starts and the actual code changes afterward.
02Independent review
Different models review the plan and code, so the author gets another perspective.
03Close the loop
Post-merge QA produces evidence. Verified cases can become follow-up automation work.
ELI5 / The simple version

Build with a plan, then show your work.

Imagine a robot helping with a building project. It needs a plan, small jobs, someone to check its work, and a notebook so it can remember where it stopped.

01Plan together
A person understands the plan before building starts.

Polaris IO

Autonomy inside explicit limits.

A typed runtime for model routing, tool execution, output validation, and cost controls.

Engineering / Architecture & tradeoffs

Host policy around a bounded model–tool loop.

01Contracts + isolation
An agent spec declares instructions, tools, output type, model tier, and limits. The host supplies configuration, enforcement, usage recording, and tracing. Tool bindings carry tenant context rather than accepting it from model arguments.
02Routing + execution
Budget checks precede model calls. Provider failover handles availability failures; schema failures can trigger escalation to a stronger tier. Tool results return to the loop under step, time, and spend limits.
03Evidence + replay
Per-call usage and redacted traces make runs inspectable. Encrypted, tenant-scoped replay of completed runs was implemented and verified locally; production rollout was pending. Recorded playback does not repeat historical tool calls.
ELI8 / How it works

An agent is a loop, not one answer.

The model may ask for a tool, read the result, and decide what to do next. The runtime manages that loop and validates the final answer.

01Before a call
Check the spending limit, choose a model, and apply the app’s rules.
02During a run
Use an allowed tool. Give its result back to the model, checking the spending limit again first.
03When things go wrong
If a model is unavailable, try another. If an answer fails a check, try a stronger model. Time and spending limits still apply.
ELI5 / The simple version

A robot with a toolbox and an allowance.

The robot can choose a tool to help with a job. Before asking its AI brain for more work, it checks whether it is allowed to spend more. It stops when it has an answer or reaches a limit.

01Choose a tool
Only the tools supplied for this job are available.

Each model call has to pass the budget check.
03Keep a receipt
Record what ran and what it cost.

Mayo Clinic

Parallel checks. A human decision.

A five-agent health-content review workflow with 34 validation rules and an explicit human handoff.

Engineering / Architecture & tradeoffs

Routed parallel validation with a human interrupt.

01Orchestration
LangGraph routes work across a five-agent workflow. Straightforward cases can clear without a model call. Checking services use Google ADK, expose agent cards, and communicate over A2A.
02Rules + resilience
A loader supplies 34 validation rules from a graph database, with a file fallback if the database is unavailable. Degradation preserves a usable review path.
03Evaluation + control
RAGAS measured groundedness and coverage before rollout. LangGraph interrupt() and a Next.js review surface keep a human approval step between generated findings and the editorial handoff.
ELI8 / How it works

Fast rules first. Specialist agents when needed.

A router handles straightforward cases without asking a model. Other articles go to specialist checking agents, whose results are combined for human review.

01Route
Use fixed checks when they can settle a case.
02Coordinate
Specialist agents work at the same time and send their findings back.
03Pause
The workflow waits for a person to review the findings before passing them on.

Handshake AI · AI Fellow

Make the test as rigorous as the task.

I author hard coding tasks and compare agents with isolated environments, independent probes, and reproducible evidence.

Engineering / Architecture & tradeoffs

Evaluation infrastructure and adversarial verification.

01Task authoring
A LangGraph toolkit models the authoring pipeline as a resumable state machine with approval gates. Local checks precede CI runs; verifier attacks probe for false passes, and real model trials calibrate difficulty.
02Comparative evaluation
Two coding agents tackle one staged task in isolated Docker containers. I inspect patches, rerun tests and load benchmarks, and write independent probes rather than relying only on agent-reported success.
03Evidence + judgment
Pair rankings cover correctness, behavior, and communication, with cited turns, test results, and hashed evidence. On an asyncio TLS task, independent probes exposed a different regression in each agent’s patch.
ELI8 / How it works

Build hard tasks, then test agents carefully.

My work spans task authoring and side-by-side evaluation. A coding challenge needs a trustworthy checker; an agent comparison needs independent testing of both results.

01Task authoring
Give the task an isolated workspace, a private checker, and a known working solution. Try to fool the checker.
02Comparative runs
Give two agents the same staged task in isolated containers. Compare code, behavior, and communication.
03Independent evidence
Rerun benchmarks and write extra probes to catch regressions the agents missed.
ELI5 / The simple version

OpenAI via Mercor · AI Evaluator

Turn a judgment into a defensible assessment.

I evaluate model-written documents and slide decks using calibrated rubrics, conformance checks, and independent critique.

Engineering / Architecture & tradeoffs

Rubric-based evaluation with an independent review layer.

01Calibrated assessment
I evaluated hundreds of model-written business documents and slide decks against multidimensional writing and visual-quality rubrics, with documented rationales tied to observed evidence.
02Conformance checks
I built checks around the rubric requirements to catch omissions and inconsistencies in evaluation drafts before submission.
03Fresh-context critique
Two independent AI judges review each draft in fresh contexts. Their critiques inform a human-reviewed final assessment; they are part of my evaluation workflow, not an autonomous replacement for judgment.
ELI8 / How it works

Quality has more than one dimension.

A document can look polished but miss the brief. A slide can be accurate but hard to read. I assess writing and visual quality using the relevant rubric and document the reasons.

01Inspect the artifact
Check the actual document or rendered deck, including the details that affect readability.
02Apply the rubric
Tie findings to the evaluation criteria and write a concrete rationale.
03Check my assessment
Checks and two separate AI reviewers critique my explanation before I make the final call.
ELI5 / The simple version

Check the homework—and the feedback.

I look at what an AI wrote or designed, compare it with clear rules, and explain what works and what needs fixing. Then I check that my feedback is fair and supported.

01Read the rules
Understand what a good result should do.
02Look closely
Read the writing and inspect the slides.
03Explain the score
Use examples from the work, then review the explanation.
